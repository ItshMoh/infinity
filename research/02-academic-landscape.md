# Long-Term Memory for LLM Agents: Academic Landscape (as of Oct 2026)

Compiled 2026-10-18 by a research subagent; every claim was checked against the linked paper/abstract/blog. Items that could not be verified are flagged at the end.

Scope: techniques for a single personal-assistant chat with "infinite" context over a user's life.

---

## 1. MemGPT (Packer et al., 2023; now Letta)
**Mechanism.** Treats the context window as RAM and external stores as disk. *Main context* = read-only system instructions + fixed-size read/write **working context** (core memory blocks) + a FIFO message queue whose first slot holds a **recursive summary** of evicted messages. *External context* = **recall storage** (every message ever, searchable) and **archival storage** (arbitrary text, pgvector). A *queue manager* emits a "memory pressure" system message at ~70% of the window so the LLM can save facts to working/archival memory, and at ~100% evicts ~50% of messages and regenerates the recursive summary. The LLM moves data itself via function calls (`core_memory_replace`, `archival_memory_search`, `conversation_search`, paginated) chained with `request_heartbeat`.
**Good at.** Persona/fact persistence in open-ended chat; DMR 93.4% (GPT-4-turbo) vs 35.3% baseline; nested KV retrieval stays flat where GPT-4 collapses to 0% at 3 nesting levels.
**Weaknesses.** Strongly dependent on function-calling quality (GPT-3.5 degraded badly); "often stops paging through retriever results before exhausting the database"; retrieval bounded by embedding search; Zep reports MemGPT "produced no successful responses" on LongMemEval. Letta's own 2025 post shows a plain filesystem + agent scores 74.0% on LoCoMo, i.e. the tiered tooling adds little on retrieval-style benchmarks.
Sources: https://arxiv.org/abs/2310.08560 , https://arxiv.org/html/2310.08560v2 , https://www.letta.com/blog/benchmarking-ai-agent-memory/

## 2. Generative Agents memory stream (Park et al., 2023)
**Mechanism.** Append-only list of natural-language records with creation and last-access timestamps. Retrieval score = α·recency + β·importance + γ·relevance (all α=1): recency = 0.995^(hours since last access); importance = LLM-rated 1–10 "poignancy" at write time; relevance = cosine similarity; each min-max normalised, top-k that fit the window are injected. **Reflection** fires when the sum of importance of recent events exceeds 150 (≈2–3×/day): prompt with the 100 most recent memories → 3 salient questions → retrieve → 5 insights with citations, stored back in the stream (reflections cite reflections → trees).
**Good at.** Cheap, interpretable, salience-aware forgetting-by-ranking; reflection gives bottom-up semantic abstraction.
**Weaknesses (authors').** Retrieval misses/fragments (remembered a planned talk but not the party); hallucinated embellishments (1.3% of 453 responses); base-model world knowledge leaks in (confused a neighbour with an 18th-century economist); errors grow as memory grows (atypical location choices); no update/contradiction logic (old and new facts coexist); importance is a one-shot LLM guess with no future-use signal.
Source: https://arxiv.org/html/2304.03442v2

## 3. A-MEM (Xu et al., 2025, Rutgers/AIOS)
**Mechanism.** Zettelkasten-style notes m_i = {content, timestamp, LLM keywords, LLM tags, LLM contextual description, embedding over all of the above, link set}. On insert: cosine top-k neighbours → LLM decides which links to form → **memory evolution**: for each neighbour the LLM may rewrite its context/keywords/tags (prompt also mentions strengthen/merge/prune but implementation unspecified). Retrieval = cosine top-k (default 10) over notes.
**Good at.** Multi-hop on LoCoMo (F1 45.85 vs MemGPT 25.52, GPT-4o-mini); ~1.2–2.5k tokens/question vs ~16.9k for MemGPT/full-context; strong on small open models.
**Weaknesses.** Trails on adversarial (50.0 vs 69.2) with GPT models; note quality depends entirely on the backbone; "Anatomy of Agentic Memory" measured ~15 h index build from super-linear consolidation; Mem0's paper reports A-Mem at J=39.8 single-hop/18.9 multi-hop (far below its own numbers—likely config differences, unresolved); no explicit contradiction/temporal invalidation—evolution rewrites descriptions rather than retiring facts.
Source: https://arxiv.org/html/2502.12110v9

## 4. HippoRAG 2 (Gutiérrez et al., ICML 2025)
**Mechanism.** Offline: LLM OpenIE extracts triples per passage → *phrase nodes* + relation edges; *synonym edges* between phrases with embedding sim > 0.8; each passage is a *passage node* linked by "contains" edges (the HippoRAG 1 → 2 change: passages are in the graph). Online: embed whole query → top-5 triples → LLM "recognition memory" filter (DSPy-tuned prompt) → seed phrase nodes (reset prob = rank score) + all passage nodes (reset prob = sim × 0.05) → Personalized PageRank (damping 0.5) → rank passages. Fallback to dense retrieval if no triples survive.
**Good at.** Associative/multi-hop recall without losing simple-QA performance: avg QA F1 59.8 vs 57.0 for NV-Embed-v2; recall@5 +13.9 on 2Wiki; "non-parametric continual learning" (add passages, no retraining).
**Weaknesses.** Error analysis: ~18% of queries end with zero triples after filtering, ~26% have no supporting-passage phrases, and in ~half of errors PPR still misses the gold passage; gains on NQ/PopQA are marginal; built for document corpora, not for updating/invalidating user facts (no temporal model); the paper notes GraphRAG/LightRAG/RAPTOR *underperform* dense RAG on simple QA.
Source: https://arxiv.org/html/2502.14802v1

## 5. Zep / Graphiti (Rasmussen et al., 2025)
**Mechanism.** Three subgraphs: *episodes* (raw messages, lossless), *semantic entities/facts*, *communities* (label-propagation clusters with map-reduce summaries, incrementally updated but needing periodic full refresh). Extraction uses current + previous 4 messages with a Reflexion-style check; entity dedup via 1024-d embedding + full-text candidates then LLM judgement; graph writes use fixed Cypher. **Bi-temporal edges**: t_valid/t_invalid (event time) and t'_created/t'_expired (ingest time); relative dates resolved against the episode timestamp. **Invalidation**: an LLM compares a new edge against semantically related existing edges and, if a temporally overlapping contradiction is found, sets old t_invalid = new t_valid (history kept, not deleted). Retrieval = cosine + BM25 + BFS from recent episodes → RRF/MMR/cross-encoder rerank → context string.
**Good at.** Temporal/point-in-time queries; LongMemEval_S 71.2% (gpt-4o) vs 60.2% full-context, with ~1.6k vs 115k context tokens and ~90% lower latency.
**Weaknesses.** Single-session-assistant category *declined* 9–17.7% (graph compresses away the assistant's own outputs); Mem0's paper measured Zep's memory footprint at >600k tokens/conversation and Mem0 beat it on single/multi-hop; MemOS's 2025 table puts Zep at 59.2 overall LoCoMo; community summaries drift; authors note weak models mishandle temporal data; LLM-based invalidation is only as good as the contradiction prompt.
Sources: https://arxiv.org/html/2501.13956v1 , https://github.com/getzep/graphiti

## 6. Mem0 / Mem0^g (Chhikara et al., 2025)
**Mechanism.** Per message pair: prompt = async-refreshed conversation summary + last m=10 messages + new pair → LLM extracts candidate memories. For each candidate: retrieve top s=10 similar memories → LLM tool-call picks **ADD / UPDATE / DELETE / NOOP**. **Mem0^g**: entity extractor + relation generator → labelled triplets in Neo4j; nodes matched by embedding threshold; an "update resolver" marks contradicted edges invalid (not deleted). Retrieval: entity-anchored traversal or semantic-triplet match.
**Good at.** Low latency (p95 total 1.44 s vs 17.1 s full-context), ~7k tokens/conversation; LoCoMo J: Mem0 66.9, Mem0^g 68.4 (vs OpenAI Memory 52.9, LangMem ~58).
**Weaknesses.** Full-context GPT-4o-mini scored 72.9%—higher than Mem0—in Mem0's own table; graph gave no gain on single/multi-hop; MemConflict found Mem0 scores 0.122 on *dynamic* (temporal-update) conflicts and has the highest runtime; MemDelta found Mem0 matches plain cloud-embedding RAG on the question types where it helps "at ~50× the cost"; DELETE is irreversible (no bitemporal history in base Mem0). Vendor 2026 claims (LoCoMo 92.5, LongMemEval 94.4, BEAM-10M 48.6) are self-reported with a new unpublished algorithm.
Sources: https://arxiv.org/html/2504.19413v1 , https://mem0.ai/blog/state-of-ai-agent-memory-2026 (vendor)

## 7. MemoryBank (Zhong et al., AAAI 2024)
**Mechanism.** Stores dialogue turns, daily event summaries and an evolving personality summary; retrieval by dense similarity. Forgetting uses the Ebbinghaus curve R = e^(−t/S): each memory has strength S starting at 1, incremented on each recall, so recalled memories decay slower; unrecalled ones drop below threshold and are dropped. Demonstrated in the "SiliconFriend" companion for ChatGPT/ChatGLM.
**Good at.** First explicit "forgetting as a feature" design aimed at companion/counselling use; cheap.
**Weaknesses.** Evaluation largely qualitative plus simulated dialogs; A-MEM's LoCoMo table shows MemoryBank far below MemGPT/A-MEM; no contradiction handling; decay is time-based only, not utility-based (the 2026 survey calls this "crude").
Source: https://arxiv.org/abs/2305.10250

## 8. Titans and parametric test-time memory (Google)
**Titans (Behrouz et al., Dec 2024).** The long-term memory is an MLP whose *weights* are updated at inference by gradient descent on an associative loss ‖M(k)−v‖²; "surprise" = that gradient, with momentum (past surprise, decay η_t), a data-dependent forgetting gate α_t (generalised weight decay), plus learnable persistent tokens. Three wirings: **MAC** (memory output concatenated as context for attention), **MAG** (gated parallel branch), **MAL** (memory as a layer before sliding-window attention). Training is parallelised via chunked matmuls. Results: S-NIAH ~95–98% at 16K, BABILong > GPT-4/Llama-3.1+RAG; the "2M+ tokens" claim appears only in figures. Ablation: removing weight decay is the most damaging.
**ATLAS (May 2025)** updates memory on a window of tokens (Omega rule) rather than one token; reports +80% on BABILong at 10M. **MIRAS ("It's All Connected", Apr 2025)** frames all of these as associative memory with four design choices (architecture, attentional-bias objective, retention gate, learning algorithm) and yields Moneta/Yaad/Memora. **Nested Learning / HOPE (NeurIPS 2025, arXiv Dec 2025)** treats the model as nested optimisation problems at different update rates, adds a self-modifying sequence model and a "Continuum Memory System" (banks updating at different frequencies) — framed as the fix for catastrophic forgetting.
**2026 successors (leads, not fully verified):** Titan-Llama (retrofitting pretrained LLMs with external neural memory, arXiv 2610.19210), End-to-End TTT for long context (2512.23675), Memory Decoder at Scale (2607.27919), Decision Titan (RL). No official Google "Titans-2" with public weights was found.
**Weaknesses for a personal assistant.** No released production checkpoints; memory is opaque (no audit, no deletion-on-request, no provenance); evaluated on NIAH/BABILong, not on user-fact updates; the 2504.15965 survey places this family in "parametric long-term" where editability and privacy are open problems.
Sources: https://arxiv.org/html/2501.00663v1 , https://arxiv.org/pdf/2505.23735 , https://arxiv.org/abs/2504.13173 , https://arxiv.org/abs/2512.24695 , https://research.google/blog/introducing-nested-learning-a-new-ml-paradigm-for-continual-learning/

## 9. Sleep-time compute (Lin, Snell, …, Packer; Letta, Apr 2025)
**Mechanism.** Split the context c from the query q; during idle time run the model over c to produce c' (pre-computed inferences, rewritten memory). In Letta, a *sleep-time agent* owns the memory-editing tools and asynchronously rewrites the primary agent's shared memory blocks into "learned context"; the primary agent only reads them. Frequency and model are configurable (bigger/slower model for sleep).
**Good at.** ~5× less test-time compute for same accuracy on Stateful GSM-Symbolic/AIME; +13–18% accuracy when scaling sleep compute; 2.5× cheaper per query when amortised over related queries.
**Weaknesses.** Benefits shrink when queries are unpredictable from context (paper's own finding); costs tokens continuously; consolidation errors are written into memory silently (see "Silent Failure" in §13); Letta gives no formal evaluation of memory-quality drift under repeated rewrites.
Sources: https://arxiv.org/abs/2504.13171 , https://letta.com/blog/sleep-time-compute

## 10. "Memory OS" and experience-memory papers (2025–26)
- **MemOS (MemTensor, Jul 2025, v4 Dec 2025).** Unifies *plaintext*, *activation* (KV-cache) and *parametric* (LoRA) memory in a **MemCube** with metadata (timestamp, provenance, type, ACL, TTL/decay, priority, access stats, version chain). MemScheduler migrates content between types (hot plaintext → KV cache; stable rules → parameters; cold params → plaintext). Lifecycle: Generated→Activated→Merged→Archived→Expired(+Frozen), with rollback. LoCoMo (GPT-4o-mini, their table): MemOS 75.8 vs Mem0 64.6, Zep 59.2, Memobase 72.0; KV injection cuts TTFT 18–94%. Best overall on MemConflict (AA 0.554). Weakness: the parametric path is largely aspirational; tables are vendor-run. https://arxiv.org/abs/2507.03724
- **MemoryOS (BUPT/Tencent, 2025).** Three tiers: STM queue of dialogue pages (len 7) → MTM topic segments via FIFO; page joins a segment if cosine+Jaccard > 0.6; segment heat = N_visit + L_interaction + e^(−Δt/μ); heat > 5 promotes facts/traits into LPM (profile, 100-slot user KB, 90 trait dims); lowest-heat segments evicted at 200. LoCoMo F1 35.3 single-hop vs MemGPT 26.7. Weakness: ~31 s retrieval/turn measured by Anatomy of Agentic Memory; many hand-set thresholds. https://arxiv.org/html/2506.06326v1
- **EverMemOS (Jan 2026).** MemCells (episodic traces + atomic facts + time-bounded "Foresight" signals) → MemScenes (thematic consolidation, profile updates) → scene-guided agentic retrieval; claims SOTA on LoCoMo/LongMemEval (numbers not retrieved from paper; vendor blog says 93.05% LoCoMo—unverified). https://arxiv.org/abs/2601.02163
- **Hindsight (Vectorize, Dec 2025).** Four networks: world facts, agent experiences, entity observations (no confidence), opinions (confidence ∈[0,1] + timestamp). Retain = LLM fact extraction with normalised time ranges + entity/temporal/causal links; recall = parallel semantic/BM25/graph-spread/temporal → RRF → cross-encoder; reflect (CARA) = disposition params (skepticism/literalism/empathy) and opinion confidence ±α, −2α on contradiction. LongMemEval_S 83.6% with a 20B OSS model (vs 39% full-context same model), 91.4% Gemini-3; LoCoMo 89.6%. Weakness: opinion/disposition machinery untested (neutral profiles), several params unspecified, no forgetting. https://arxiv.org/html/2512.12818
- **Memp (ZJU, 2025).** Procedural memory from trajectories as verbatim steps and/or distilled scripts; retrieval by query or keyword-averaged embeddings; update strategies: append all, keep-only-success, reflexion-style revise-on-failure (best). ALFWorld success 42→78% (GPT-4o); memory built by GPT-4o helps Qwen-14B. Needs an external reward signal. https://arxiv.org/html/2508.06433v3
- **Memento (2025).** Memory-augmented MDP: a case bank of (state, action, reward); a small learned case-retrieval policy is trained online while the LLM is frozen. https://arxiv.org/abs/2508.16153
- **ReasoningBank (Google, ICLR 2026).** Distils *strategies* (not trajectories) from self-judged successes and failures; MaTTS runs extra rollouts to get contrastive signal for memory. Beats raw-trajectory memory on WebArena/Mind2Web/SWE-bench. https://arxiv.org/abs/2509.25140
- **FadeMem (Jan 2026).** Dual-layer store with adaptive exponential decay modulated by relevance, access frequency and temporal pattern, plus LLM fusion; 45% storage reduction on MSC/LoCoMo. https://arxiv.org/abs/2601.18642

## 11. Reflexion (Shinn et al., NeurIPS 2023)
**Mechanism.** After a failed trial the agent writes a verbal self-reflection from scalar/free-form feedback; reflections are stored in a bounded sliding-window episodic buffer and prepended to subsequent trials. No weight updates. HumanEval 91% pass@1.
**Good at.** Fast self-improvement where failures are diagnosable and feedback exists.
**Weaknesses.** Depends on self-evaluation quality; verbal notes don't fix exploration failures; buffer is small; for a lifelong assistant there is no principled consolidation of reflections (the ReasoningBank/Memp lines exist precisely to fix this). Limitations here come from secondary commentary, not the paper's own section.
Source: https://arxiv.org/abs/2303.11366

## 12. Surveys and their taxonomies
- **Zhang et al. 2024 (RUC/Huawei).** Sources: inside-trial / cross-trial / external knowledge. Forms: textual vs parametric. Operations: write, manage, read. https://arxiv.org/abs/2404.13501
- **"From Human Memory to AI Memory" (Apr 2025).** 3D-8Q: object (personal vs system) × form (parametric vs non-parametric) × time (short vs long). Maps human types: episodic ≈ non-parametric personal long-term (Mem0, ChatGPT Memory); semantic ≈ parametric; procedural ≈ system long-term (Voyager, ExpeL). Open problems: multimodal, streaming, shared, collective privacy, automated evolution. https://arxiv.org/html/2504.15965v2
- **"Rethinking Memory in LLM-based Agents" (May 2025).** Representations: parametric vs contextual-structured vs contextual-unstructured. Six atomic operations: consolidation, updating, indexing, forgetting, retrieval, condensation. https://arxiv.org/abs/2505.00675
- **"Memory in the Age of AI Agents" (Hu et al., Dec 2025/Jan 2026, ~45 authors).** Forms: token-level (1D flat / 2D tree-graph / 3D hierarchical), parametric (internal weights; external adapters), latent. Functions: factual (user/environment), experiential (case/strategy/skill), working. Dynamics: formation, evolution (consolidation, updating, forgetting: time-/frequency-/importance-based), retrieval. Argues short/long-term is "insufficient" and episodic/semantic/declarative terminology causes "conceptual fragmentation." Frontiers: memory automation, RL, multimodal, multi-agent, trustworthiness. https://arxiv.org/html/2512.13564v2
- **"Memory for Autonomous LLM Agents" (Mar 2026).** Axes: temporal scope (working/episodic/semantic/procedural) × substrate (context, vector, structured, executable, hybrid) × control (heuristic, prompted, learned). Says consolidation is "rarely automatic," forgetting is "hard expiry, eviction, or nothing," and "nobody evaluates forgetting well"; proposes a probationary dual-buffer before consolidation. https://arxiv.org/html/2603.07670v1
- **"Anatomy of Agentic Memory" (Feb 2026).** Four structures: lightweight semantic; entity-centric/personalized; episodic & reflective; structured/hierarchical. Empirical: LoCoMo (~20k tokens) "remains comfortably in-window"; proposes reporting Δ = Score_memory − Score_fullcontext; weak backbones cause "silent" write-format errors (Nemori 17.9%→30.4% with Qwen-3B). https://arxiv.org/html/2602.19320v1

**Methodological critiques to take seriously.**
- **Mem0 vs Zep**: Mem0 (issue #5) showed Zep's 84% included adversarial Qs in numerator only → Zep corrected to 75.14%; Zep showed Mem0 misconfigured Zep (both speakers as "user", timestamps in text not `created_at`, serial searches) and that Mem0's own full-context baseline (72.9) beat Mem0 (68.4). An independent rerun (arXiv 2601.07978) got Graphiti 56.0 vs Mem0 81.1 — directionally opposite. Nothing is reconciled. https://github.com/getzep/zep-papers/issues/5 , https://www.getzep.com/blog/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/
- **MemDelta** (Jun 2026): verbatim RAG ≈ full-context (47.2 vs 49.8, p=0.34); swapping *only* the embedding model moves accuracy +6.2 pp; Sonnet gains +31 pp from RAG partly because it refuses 63% of full-context queries. https://arxiv.org/abs/2606.29914
- **Fidelity Before Structure** (Jan 2026): verbatim chunks 67.4% vs extracted facts 45.4% on LongMemEval_S; accuracy "tracks how much source text survives." Keep raw text; add structure on top. https://arxiv.org/abs/2601.00821
- **Goal-Directed Search** (SUMER, Nov 2025): an RL-trained search agent over uncompressed logs beats all compression systems and full-context on LoCoMo. https://arxiv.org/abs/2511.21726
- **When Does Memory Help** (Sep 2026): on *updated* facts embedding retrieval ranges 0.30–0.95 across seeds; agents act on a correctly retrieved value only 55% of the time; update-on-write stores 0.70–1.00; implementation choice alone swings success 60 points. https://arxiv.org/abs/2609.05441

## 14. Affect, mood, user modelling, theory of mind
- **Dynamic Affective Memory Management** (Oct 2025): self-managed memory vector DB updated by a Bayesian-inspired rule that minimises "memory entropy"; proposes DABench for emotional expression/change toward objects; claims less bloat. Mechanism details and numbers not in abstract — unverified. https://arxiv.org/abs/2510.27418
- **REMT** (Frontiers in AI, 2026): each exchange is a node with embedding + normalised valence + tags + timestamps; edges weighted by semantic, affective, symbolic and temporal proximity; a global **Mood Index ∈[−1,1]** aggregates valence of recently activated nodes and biases retrieval toward mood-congruent memories; edges reinforce on activation, decay exponentially, prune below threshold. **No empirical results**; proprietary test env; flags manipulation/dependency risks. https://www.frontiersin.org/journals/artificial-intelligence/articles/10.3389/frai.2026.1749517/full
- **The Personalization Trap** (ACL 2026): injecting a user profile as memory changed emotional-reasoning accuracy for 11/15 models, mostly *downward* (Claude 3.7: 90.9 → 80.1/77.4 advantaged/disadvantaged); bias along gender/age/religion; "persona distraction." Direct warning for mood-aware assistants. https://arxiv.org/html/2510.09905v1
- **Mind2Dialogue** (Sep 2026): simulator maintains an evolving user mental state; an oracle assistant with access to it provides supervision; distilled models gain 26.6–40.9 pp preference-following without the state at test time. Self-reported. https://arxiv.org/abs/2609.15972
- Hindsight's CARA disposition/opinion-confidence model (above) is the most concrete "beliefs about the user with confidence" design, but was not evaluated.
- Emotion-weighted retrieval is noted in the artificial-emotion survey (https://arxiv.org/pdf/2508.10286) on InCharacter-MBTI only.

## 15. Consolidation, forgetting, temporal updates, hierarchical summarisation (2025–26)
- **Temporal Semantic Memory (Jan 2026)**: separates *event time* from *dialogue time*; facts in a temporal KG with validity intervals used as an index; monthly slices → GMM clusters → LLM topic & persona summaries; spaCy parses "last weekend" into a range; rerank by time match first, similarity second. LongMemEval_S 74.8 (temporal 69.9 vs 47.4). https://arxiv.org/html/2601.07468v1
- **Episodic-to-Semantic Consolidation Without Identity Drift (Jul 2026)**: deterministic f: M_ep → M_sem into auditable rows with confidence + supporting-event links; identity manifest never reads semantic layer; −79.8% wasted planner attempts. Synthetic eval. https://arxiv.org/abs/2607.01988
- **REALM retrieval-driven reconsolidation (Sep 2026)**: memories reorganised on *retrieval feedback*, not only on write; LoCoMo 75.97, LongMemEval 65.11 (+1.3 only). https://arxiv.org/abs/2609.16053
- **Forgetting as a feature**: FadeMem (above); FSFM selective forgetting (+29% SNR, arXiv 2604.20300); DREAM uses decay to purge poisoned memories (2610.13267); Bemula benchmarks forget-on-request (2610.18052); Selective-Forgetting graph (2608.28978).
- **Contradictions**: TOKI "bitemporal operator algebra" (2606.06240, title only); MemConflict and BEAM both find contradiction resolution is the weakest capability across systems.
- **Hierarchical summarisation**: **RAPTOR** (ICLR 2024) clusters chunk embeddings (UMAP+GMM) and summarises recursively into a tree; retrieve by traversal or collapsed tree; +20% on QuALITY — but HippoRAG 2 shows its summaries add noise on simple QA. https://proceedings.iclr.cc/paper_files/paper/2024/hash/8a2acd174940dbca361a6398a4f9df91-Abstract-Conference.html **Recursively Summarizing** (Wang et al., Neurocomputing 2025): fold each new dialogue chunk into one running summary; Zep's DMR test puts recursive summarisation at 35.3% vs 93–94% for MemGPT/full-context — lossy single-summary memory fails on specifics. https://arxiv.org/abs/2308.15022

## Practical takeaways for a "whole life" assistant (grounded in the above)
1. **Never discard verbatim text.** Three independent 2026 studies (Fidelity Before Structure, MemDelta, SUMER) show extracted-fact or summary stores lose 15–22 points vs raw chunks; structure should index raw episodes, not replace them.
2. **Temporal validity is the differentiator for life-long data.** Bi-temporal edges (Zep), event-time intervals (TSM) and invalidate-don't-delete (Mem0^g) are the only mechanisms that handle "I moved / broke up / changed jobs"; yet every benchmark (MemConflict, BEAM, Memora, When-Does-Memory-Help) still rates contradiction handling as the weakest capability.
3. **Consolidation needs a probation stage and audit trail**; weak backbones silently corrupt memory on write (Anatomy of Agentic Memory), and reconsolidation-on-retrieval (REALM) and sleep-time rewriting have no drift metrics yet.
4. **Mood/affect memory is almost entirely unvalidated**, and the one rigorous study (Personalization Trap) shows injected user profiles *degrade* emotional reasoning and introduce demographic bias.
5. **Treat all vendor LoCoMo/LongMemEval numbers as incomparable**; the only robust signal is Δ vs a full-context/verbatim-RAG baseline with a fixed embedding model and judge.
