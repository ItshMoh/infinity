# Production & open-source LLM memory systems — how they actually work (as of Oct 2026)

Compiled 2026-10-18 by a research subagent. Scope: internals, trade-offs, and complaints for each system. Vendor claims are labelled as such; items that could not be confirmed from a primary source are flagged **[unverified]**. OpenAI's own pages (openai.com, help.openai.com) returned 403 to the fetcher, so ChatGPT internals rest on reverse-engineering write-ups plus press coverage of OpenAI's June 2026 post.

## 0. The three architectures that actually ship

Every system below is one of three shapes (or a hybrid):

1. **Pre-computed profile injected every turn** — ChatGPT, Gemini (likely), Supermemory "profile" mode, Memobase, Claude's legacy Team "memory summary". Cheap at inference, no tool-call non-determinism, but lossy and opaque; users complain about "dossiers" and bleed-through.
2. **Agent-driven retrieval over raw history via tools** — Claude.ai (`conversation_search`/`recent_chats`), Claude API memory tool, Claude Code auto memory, Letta MemFS, OpenClaw `memory_search`. Transparent and precise, but only works when the model decides to search.
3. **Extraction pipeline → store (vector/graph/SQL) → top-k injection** — Mem0, Zep/Graphiti, Hindsight, Cognee, LangMem, Honcho. Best benchmark numbers, worst failure modes (junk extraction, feedback loops, contradictions, ingestion cost).

Almost everyone converged in 2026 on a **background "sleep"/"dreaming" consolidation pass** (OpenAI "Dreaming", OpenClaw dreaming, Letta sleep-time → client-side subagent reflection, Mem0 "Dream", Honcho "Dreamer", Supermemory `dreaming: "dynamic"`).

## 1. ChatGPT memory (OpenAI)

**Two user-facing features** (2024–2025): *Saved memories* (explicit facts via a `bio` tool) and *Reference chat history* (inferred profile from past chats). No RAG over history.

**What's injected (reverse-engineered, 2025):** Johann Rehberger dumped the system prompt and found six sections ([Embrace The Red](https://embracethered.com/blog/posts/2025/chatgpt-how-does-chat-history-memory-preferences-work/)):
- **Model Set Context** — saved memories, each timestamped (the `bio` tool output).
- **Assistant Response Preferences** — ~15 inferred style preferences, each tagged `Confidence: high`.
- **Notable Past Conversation Topic Highlights** — ~8 summaries.
- **Helpful User Insights** — ~12–14 profile bullets (name, job, location, expertise).
- **Recent Conversation Content** — ~40 recent chats: timestamp + short summary + **only the user's messages** (joined with `||||`); assistant replies excluded (Rehberger suspects this limits prompt-injection/hallucination carry-over).
- **User Interaction Metadata** — ~12–17 auto fields: plan, device, locale, account age, usage patterns, internal `intent_tags`.

Manthan Gupta's Dec 2025 probe agrees on the layering (metadata → long-term facts → recent-conversation summaries → current session, user-only, ~15 summaries, token-based rolling window) and stresses it's pre-computed, not retrieved ([manthanguptaa.in](https://manthanguptaa.in/posts/chatgpt_memory/), [LLMrefs summary](https://llmrefs.com/blog/reverse-engineering-chatgpt-memory)). Simon Willison called it a "memory dossier" ([simonwillison.net May 2025](https://simonwillison.net/2025/May/21/chatgpt-new-memory/)). Note: no write-up by an "Eric Hayes" was found; the canonical sources are Rehberger, Shlok Khemani, Gupta and Willison **[unverified attribution]**.

**2026 changes:**
- **May 2026 "memory sources"**: a Sources icon shows which saved memories / past chats / Gmail items shaped a reply ([release-notes summary](https://knightli.com/en/2026/05/07/chatgpt-release-notes-memory-gpt-5-5-sheets/)).
- **June 4, 2026 "Dreaming"** ([Sam Altman tweet](https://x.com/sama/status/2062660086787613116), [Neowin](https://www.neowin.net/news/openai-is-rolling-out-a-major-upgrade-to-chatgpt-memory/), [XDA](https://www.xda-developers.com/chatgpt-quietly-rewrites-its-memories-of-you-not-sure-i-like-it/)): a periodic, asynchronous background pass that re-reads recent conversations, adds facts, corrects stale ones, drops irrelevant ones, and **re-writes time-bound facts** ("going to Singapore in July" → "went to Singapore in July 2026"). Saved memories are no longer the primary store. OpenAI claims factual recall 41.5% (2024 saved-memories system) → 82.8%, "~5x compute efficiency", ~2x capacity for Plus/Pro **[vendor claims; some outlets cite 67.9% as the baseline]**. A new **Memory Summary** page in settings is an LLM-generated, natural-language-editable view.
- Shlok Khemani's analysis ([shloked.com](https://www.shloked.com/chatgpt-memory-2026)): the Memory Summary is a *partial, regenerated-on-view subset* of a denser hidden "User Knowledge memories" profile and "never enters the context window"; edits are stored as conversations and reach the model through chat history, likely because regenerating the dense profile per edit is too expensive. He calls this a "packaging problem".

**Complaints:** unrequested bleed-through (Willison's "Half Moon Bay" sign); over-personalization skewing unrelated tasks; "saved memory full" caps (~100–150 entries reported **[unverified]**); the summary "won't show everything"; no single place to fully delete a memory ("Don't mention this again" only suppresses); shared accounts produce merged profiles (XDA); background rewriting without consent; indirect prompt injection can write to `bio` (Rehberger). Mem0 wrote a long explainer on the Dreaming change but it is a competitor's article and paywalled ([x.com/mem0ai article](https://x.com/mem0ai/article/2071990201531118063)).

**Developer side (Responses API / Agents SDK):** no long-term memory product. State = (a) resend messages, (b) `previous_response_id` chaining (all prior input tokens re-billed; responses stored 30 days unless `store=false`), (c) **Conversations API** object (durable, not subject to 30-day limit). **Compaction** is new: `context_management: {type: "compaction", compact_threshold}` on `/responses`, or a standalone `/responses/compact` endpoint that returns an *encrypted, opaque* compaction item carrying prior state/reasoning ([conversation-state guide](https://developers.openai.com/api/docs/guides/conversation-state), [compaction guide](https://developers.openai.com/api/docs/guides/compaction)). Agents SDK "Sessions" are pluggable history stores (SQLite, Redis, Mongo, OpenAIConversationsSession, EncryptedSession with TTL) plus `OpenAIResponsesCompactionSession` and a `SessionSettings(limit=N)` trimmer — nothing semantic ([Agents SDK sessions](https://openai.github.io/openai-agents-python/sessions/)).

## 2. Claude (Anthropic)

### Consumer (claude.ai)
Three pieces ([Anthropic help center](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)):
- **Memory**: Claude "saves a set of individual topics as you chat, rather than summarizing conversations after they end." Updates live; on by default for Free/Pro/Max (opt-in for Team/Enterprise). Sensitive topics (health/politics/religion) excluded unless opted in; gov-ID/financial numbers never stored. Deleting a chat does **not** delete memories derived from it. Viewable/editable under Settings → Memory → Topics; changes apply to the *next* conversation. **Project memory** is per-project and isolated.
- **Chat search** (paid plans): explicit RAG over past chats, surfaced as **visible tool calls** with citations; never searches incognito chats.
- **Legacy "memory summary"** (Team/Enterprise only): synthesized from non-project chats every 24h — this is where third-party "updates every 24h" claims come from.

Reverse-engineered internals ([Gupta, Dec 2025](https://manthanguptaa.in/posts/claude_memory); [Willison, Sept 2025](https://simonwillison.net/2025/Sep/12/claude-memory/)): memories injected as an XML-ish `<userMemories>` bulleted block; a `memory_user_edits` tool for "remember/forget this"; `conversation_search(query, max_results 1–10, default 5)` and `recent_chats(n 1–20, sort_order, before, after)` return `<chat>` entries with URL, `updated_at`, title and snippets; reported ~190k-token budget **[unverified, model self-report]**. Willison's verdict: more transparent than ChatGPT, but recall depends on the model choosing to call a tool.

### Developer platform
- **Memory tool** (`memory_20250818`, client-side; all Claude 4+ models) ([docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)): six commands (`view`, `create`, `str_replace`, `insert`, `delete`, `rename`) over a `/memories` prefix **you** map to storage. When present, the API auto-prepends a system instruction: *"ALWAYS VIEW YOUR MEMORY DIRECTORY BEFORE DOING ANYTHING ELSE … ASSUME INTERRUPTION: your context window might be reset at any moment."* Files >16,000 chars are truncated on `view`. Security burden is yours (path traversal, size caps, expiry). Recommended "multisession pattern": progress log + feature checklist files.
- **Context editing** (beta header `context-management-2025-06-27`) ([docs](https://platform.claude.com/docs/en/build-with-claude/context-editing)): `clear_tool_uses_20250919` (default trigger 100k input tokens, keep 3 most recent tool uses, `clear_at_least`, `exclude_tools`) and `clear_thinking_20251015`. Clearing invalidates prompt cache at the cut point. When memory tool + clearing are combined, Claude gets an automatic warning to save to memory before results are cleared.
- **Server-side compaction** ([overview](https://platform.claude.com/docs/en/build-with-claude/compaction)): *on demand* (header `compact-2026-09-04`, top-level `compaction` param; can keep recent turns verbatim, run in background) or *at a token threshold* (`compact_20260112` edit). Client SDK compaction (`compaction_control`) is deprecated.
- **Context-engineering guidance** ([Anthropic engineering post](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)): context is "a finite resource with diminishing marginal returns"; prefer just-in-time retrieval via lightweight identifiers (paths, queries) over pre-loading; three long-horizon techniques — compaction (tune for recall first, then precision; clearing tool results is the "lightest touch"), structured note-taking (NOTES.md / memory tool), and sub-agents returning 1–2k-token distilled summaries.

### Claude Code ([memory docs](https://code.claude.com/docs/en/memory), [model-config](https://code.claude.com/docs/en/model-config))
- **CLAUDE.md** hierarchy (managed/user/project/local, `.claude/rules/` path-scoped, `@imports` that still load at launch); target <200 lines; files >4 MiB skipped.
- **Auto memory** (default on, v2.1.32+): Claude writes `~/.claude/projects/<project>/memory/MEMORY.md` (index, one line per memory) plus topic files with frontmatter `type: user|feedback|project|reference`. **Only the first 200 lines / 25 KB of MEMORY.md load at session start**; topic files are read on demand; over-limit writes succeed but return an error telling Claude to rewrite the index. Shared across worktrees, machine-local, excluded from transcript cleanup.
- **Auto-compaction**: triggers at the model's context limit by default (~967K on native-1M models; 200K for Sonnet/Opus 4.6 without `[1m]`); configurable via `/autocompact <size>`, `autoCompactWindow`, `--autocompact`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW` (100K–1M); `idleCompaction` also exists. Third-party claims of "83.5%/150K" triggers are stale **[unverified]**.

**Complaints:** adherence drops with long CLAUDE.md; memory only "context, not enforced configuration"; search-based recall misses when Claude doesn't invoke the tool; memory not shared across machines.

## 3. Gemini (Google)

Settings → **Personal Intelligence**: *Memory* (past chats; renamed from Aug-2025 "Personal context"), *Connected apps* (Gmail, Photos, YouTube, Search — opt-in, US beta Jan 2026 for AI Pro/Ultra), *Preferences* ([help index](https://support.google.com/gemini/answer/15637730), [past-chats article](https://support.google.com/gemini/answer/16598469), [Google blog](https://blog.google/innovation-and-ai/products/gemini-app/personal-intelligence/)). Requires personal account, 18+, *Keep Activity on* (memory works off stored Gemini Apps Activity — turning activity off kills memory). Not in Gems or Live. Google says Gemini "determines if your custom instructions, past chats, or connected apps could be helpful" per prompt, cites what it used, and you can ask "Did you use any info from past chats?" Deletion = delete the underlying chats (takes time to propagate). Not available in EEA/UK/CH **[third-party]**. **Internals are undocumented**; third-party blogs claim profile-style summaries rather than transcript search **[unverified]**. For developers, Vertex AI Agent Engine "Memory Bank" offers identity-scoped persistence **[not fetched]**. Complaints: incomplete retrieval over large mailboxes; golf-photo-style over-inference (Google's own example); no view of what's stored.

## 4. Letta (ex-MemGPT)

**Classic model** (still in docs): **memory blocks** (`label`, `description`, `value`, `limit` in chars, `read_only`) rendered into the system prompt in an XML-like `<memory_blocks>` section showing current/max chars; default `persona` + `human`; shared blocks across agents (last write wins). Agent self-edits via `memory_replace/insert/rethink`; **archival memory** = vector store via `archival_memory_insert/search`; **recall** = `conversation_search` over full DB-persisted history; evicted messages are never lost ([memory docs](https://docs.letta.com/guides/agents/memory), [blocks](https://docs.letta.com/guides/agents/memory-blocks)). **Sleep-time agents** (Apr 2025): a paired background agent that owns block editing while the primary only reads ([blog](https://www.letta.com/blog/sleep-time-compute/)); community found sleep-time archival too slow to guarantee availability before the reply ([forum](https://forum.letta.com/t/should-archival-memories-be-managed-by-a-sleeptime-agent/74)).

**2026 pivot** ([Letta's Next Phase, Mar 2026](https://www.letta.com/blog/our-next-phase/), [Context Repositories, Feb 2026](https://www.letta.com/blog/context-repositories)): memory moves to **MemFS / "context repositories"** — a git-backed directory cloned locally. `system/` files are always fully in the system prompt; the full file tree (with per-file frontmatter descriptions) is always in the prompt as navigation; everything else is read via bash/file tools. Every change is a git commit; subagents get worktrees for concurrent writes; **background reflection** runs in a worktree and merges; a "defragmentation" skill restructures into 15–25 files. Server-side memory tools (`core_memory_replace`), Letta Filesystem, templates, identities and server-side sleep-time agents are deprecated in favour of client-side subagents. **Letta Code** (Apache-2.0 harness) adds `project`, `skills`, `loaded_skills`, `style` blocks and a `/init` that fans out over Claude Code/Codex histories ([gist deep-dive](https://gist.github.com/monotykamary/89226f685c17841d4d910c30b6b88442)). "Dreaming" runs after N steps or on compaction ([config](https://docs.letta.com/configuration/memory)).

**Complaints:** runaway `human` block crowding context; agent overwriting its persona; silent truncation at block limits **[unverified]**; churn from the 2026 deprecations invalidating tutorials.

## 5. Mem0

**Paper pipeline** (arXiv 2504.19413): extraction LLM pulls facts from each message pair using a rolling summary + recent messages; then per-fact similarity search and a tool-call choosing ADD/UPDATE/DELETE/NOOP; graph variant extracts triplets and *invalidates* conflicting edges. Defaults: `gpt-5-mini` + `text-embedding-3-small` ([repo](https://github.com/mem0ai/mem0)).

**2026 reality — this changed:** the v3 rewrite (2026-04-14) made extraction **ADD-only** ("Memories accumulate; nothing is overwritten or deleted") because the update prompt needed one LLM call per candidate ([changelog](https://docs.mem0.ai/changelog/highlights), [ops docs](https://docs.mem0.ai/core-concepts/memory-operations)). Retrieval is hybrid (semantic + BM25 + entity boost, parallel) targeting <7K tokens; graph DB backends were removed in favour of built-in entity linking; **temporal reasoning** (May 2026) resolves "last week"/"before SF"; **memory decay** (May 2026, off by default) biases ranking 0.3×–1.5× by recency of *use*; **"Dream" consolidation** (Sep 2026, Pro $249/mo+) does Supersede/Merge/Synthesis in the background, keeps both versions, `latest_only=true` for current truth **[third-party description]**. Contradictions therefore live in the store until Dream runs — GitHub issue [#5867](https://github.com/mem0ai/mem0/issues/5867) ("Ronaldo → Messi both stored") is open as a "product decision".

**Benchmarks:** platform LoCoMo 91.6–92.5, LongMemEval 93.4–94.4, p50 ~0.9–1.1s, ~7K tokens — self-reported, platform-only optimizations, and the README and changelog disagree on the numbers **[inconsistent]**. Zep's "Lies, Damn Lies" post alleges Mem0 misconfigured Zep (both speakers as `user`, timestamps in text, sequential search) ([Zep rebuttal](https://www.getzep.com/blog/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/)); Mem0's CTO counter-alleged Zep used excluded adversarial categories; Zep later corrected its own figure (75.14%). Unresolved.

**Complaints (the sharpest in this survey):** a 32-day production audit found **97.8% of 10,134 memories were junk** — boot-file restating every session (52.7%), a **recall feedback loop** (recalled memories re-extracted as new; 808 "User prefers Vim" entries, nobody uses Vim), 4,000-word architecture dumps, leaked IPs, a hallucinated "John Doe" user with a 2B model ([issue #4573](https://github.com/mem0ai/mem0/issues/4573)). Casual remarks become blanket preferences; dates get rewritten vs verbatim chunks ([arXiv 2601.00821](https://arxiv.org/pdf/2601.00821)); every add is an LLM call. Pricing: Hobby free (~10k memories/1k retrievals), Starter $19, Pro $249, graph/Dream gated to Pro **[aggregator figures]**.

## 6. Zep / Graphiti

**Graphiti** (Apache-2.0, [repo](https://github.com/getzep/graphiti)): episodes → LLM entity/edge extraction with structured output → **bi-temporal** edges (validity window + ingestion time); contradicting facts are **invalidated, not deleted**; hybrid retrieval = embeddings + BM25 + graph traversal, optional graph-distance/cross-encoder reranking; Neo4j/FalkorDB/Neptune (Kuzu deprecated); default OpenAI; `SEMAPHORE_LIMIT=10` to dodge 429s. Needs structured-output-capable models; small/local models break ingestion.

**Zep Cloud** adds users, threads, "Smart Context Assembly" and a **Context Block**: a labelled text block of user summary, facts with "from–to / present" validity, entities, episodes, observations, thread summaries; built by `thread.get_context` using the last four messages as auto-query ([concepts](https://help.getzep.com/concepts), [retrieving context](https://help.getzep.com/retrieving-context)). Notably Zep says **keep the block out of the system prompt** — place it after history and before the latest user message (or as a `tool_result` for Anthropic), replace each turn, and still send the last 4–6 raw messages because they may not be in the graph yet. Claims: sub-200ms retrieval, LongMemEval 71.2% (GPT-4o) in a peer-reviewed paper ([arXiv 2501.13956](https://arxiv.org/pdf/2501.13956)).

**Complaints:** ingestion is expensive — ~4 LLM calls floor + 1–2 per edge per episode ([production guide](https://renezander.com/guides/graphiti-in-production/)); Zep's own post describes episode processing hitting 60s and LLM cost at 3–5x capacity before they replaced calls with entropy/TF-IDF/LSH heuristics ([scaling post](https://blog.getzep.com/scaling-agent-memory-zep-30x/)); third-party bench 3.65s ingest/turn; you must run a graph DB; self-hosted Zep CE deprecated Apr 2025; Flex plan ~$104–125/mo credit-based **[aggregator]**.

## 7. Supermemory

Closed-source engine, MIT-licensed SDKs/MCP/plugins and a local binary (`npx supermemory local`, `~/.supermemory`, hosted reader still used for URLs) ([repo](https://github.com/supermemoryai/supermemory)). Ingest: queued → extracting → chunking → embedding; `dreaming: "dynamic"` (default) batches related docs so new namespaces show nothing for minutes; `taskType: "superrag"` skips fact extraction (5x cheaper) ([Memory API overview](https://supermemory.ai/docs/memory-api/overview)). Engine "extracts facts, tracks updates, resolves contradictions, auto-forgets expired info"; **user profile = static facts + dynamic recent context**, "~50ms" profile fetch (no methodology). **Memory Router / `withSupermemory`**: swap the base URL or wrap the model; per call it retrieves `profile` (default) / `query` / `full`, injects via a template, drops tool calls by default, writes memories async, and **silently degrades to no memory on error** (`skipMemoryOnError: true`) ([router overview](https://supermemory.ai/docs/memory-router/overview)). "Infinite Chat" (Jul 2025) = conversation-ID backfill + summarize/prune + tracking already-seen chunks instead of stuffing 10 passages ([blog](https://supermemory.ai/blog/faster-smarter-reliable-infinite-chat-supermemory-is-context-engineering/)). Internals (atomic facts, versioning edges, temporal grounding) described only by third parties **[unverified]**; "up to 70% token savings" and "sub-300ms p50" are vendor claims. Complaints: 5-hour degradation on Mar 6 2026 with failed alerting ([incident report](https://blog.supermemory.ai/incident-report-march-2026)); minutes-long indexing delay in dynamic mode.

## 8. Honcho (Plastic Labs) — user modelling

Open-source ([repo](https://github.com/plastic-labs/honcho)); data model = workspaces → **peers** (users *and* agents) → sessions → messages. Two layers ([architecture](https://honcho.dev/docs/v2/documentation/core-concepts/architecture), [representation](https://honcho.dev/docs/v3/documentation/core-concepts/representation), [CLAUDE.md](https://github.com/plastic-labs/honcho/blob/main/CLAUDE.md)):
- **Deriver** (background, single structured-output LLM call per batch; `DERIVER__MAX_INPUT_TOKENS` 25k): extracts **explicit** and **deductive** conclusions into `(observer, observed)` pgvector collections (self = observer==observed); summaries every 20 (short) / 60 (long, recursive) messages; tasks for the same peer run serially in order. `observe_me` builds a **global** representation from all of a peer's messages; `observe_others` builds **local** representations (Alice's model of Bob) — the theory-of-mind angle.
- **Dreamer** (off-queue, surprisal-prioritized): DeductionSpecialist then InductionSpecialist produce higher-order conclusions and update a cached **peer card** (name/occupation/interests); every conclusion links to its premises (`get_reasoning_chain`).
- **Dialectic `/chat`**: the only synchronous tool-using agent — you ask natural-language questions *about* a peer ("what's the user's mood today?") and it loops over `search_memory`, `search_messages`, `grep_messages`, date-range/temporal search, `get_observation_context`, `get_reasoning_chain`; five reasoning tiers (minimal…max) each with their own model. `get_context` returns summaries + recent messages for the next completion.
Gotchas: with `FLUSH_ENABLED` off the deriver waits for a 1024-token batch ([self-hosting write-up](https://techblog.cosmohub.work/self-hosting-honcho-agent-memory-that-actually-works/)); code says "observations", API says "conclusions"; dialectic adds an LLM round-trip per answer. Integrations: Hermes, OpenClaw plugin.

## 9. LangMem (LangChain)

Library, storage-agnostic core ([concepts](https://langchain-ai.github.io/langmem/concepts/conceptual_guide/)): **semantic** memory as *collections* (many records; insert/update/invalidate; recall by similarity + importance + recency) or *profiles* (one schema'd doc updated in place); **episodic** (situation/reasoning/action/outcome examples); **procedural** (the system prompt itself, refined by prompt optimizers: metaprompt / gradient / prompt_memory). Formation is **hot-path** (tool call, adds latency) or **background** via `ReflectionExecutor.submit(after_seconds=…)` — debounced per thread (new messages cancel and reschedule; docs suggest 30–60 min), local or LangGraph-Platform remote ([delayed processing](https://langchain-ai.github.io/langmem/guides/delayed_processing/)). Storage = LangGraph `BaseStore` namespaces (e.g. `("memories", "{user_id}")`). No benchmarks; complaints are mostly "it's a thin layer, you build the rest".

## 10. Others (brief)

- **Hindsight (vectorize.io)** — open source; *retain/recall/reflect*; four networks (world facts, experiences, entity observations, opinions with confidence) on Postgres+pgvector; retrieval mixes semantic/keyword/graph/temporal under a token budget. LongMemEval 83.6% with GPT-OSS-20B (vs 39% full-context same model), 91.4% with Gemini-3 Pro; LoCoMo 89.61% ([arXiv 2512.12818](https://arxiv.org/abs/2512.12818), [blog](https://vectorize.io/blog/introducing-hindsight-agent-memory-that-works-like-human-memory)). "Independently verified by Virginia Tech" **[unverified]**.
- **Memobase** — profile-based: `topic/sub_topic/content` slots + event timeline; per-user buffer flushes at ~1024 tokens or ~1h idle; `u.context(max_token_size, prefer_topics)` packs profile + events into one string; fixed 3 LLM calls per flush; <100ms profile reads via SQL ([repo](https://github.com/memodb-io/memobase)). Closest open-source analogue to ChatGPT's approach.
- **Memori (GibsonAI)** — Apache-2.0, plain SQL (SQLite/Postgres/MySQL), background augmentation into attributes/events/facts/people/preferences/rules/skills, scoped by entity/process/session ([repo](https://github.com/GibsonAI/memori)).
- **Cognee** — Apache-2.0 `remember/recall/improve/forget`; text → entities/relationships/chunks across relational+vector+graph (Postgres-only "demo" mode; Kuzu); "session distillation" promotes lessons; BEAM 0.79 @100K / 0.67 @10M self-reported ([repo](https://github.com/topoteretes/cognee)).
- **Memary** — LlamaIndex KG (Neo4j/FalkorDB) + "memory stream" (entity timestamps) + "entity knowledge store" (frequency/recency), 2-hop subgraph retrieval; README's own sort looks inverted; low activity ([repo](https://github.com/kingjulio8238/Memary)).
- **MemoRizz** — experimental, PolyForm-Noncommercial, MongoDB/Oracle/filesystem providers; episodic/semantic/procedural/short-term/shared types ([repo](https://github.com/RichmondAlake/memorizz)).
- **Vectara** — in-session artifacts + cross-session memory as an indexed corpus ([docs](https://docs.vectara.com/docs/agents/memory)). **mem.ai** — notes app with a per-person "memory graph"; no technical disclosure.
- **Limitless/Rewind** — pendant transcription + searchable summaries; **acquired by Meta Dec 2025**, sales stopped, Rewind desktop capture sunset, EU/UK data deletion; no architecture published ([coverage](https://aibusiness.com/speech-recognition/meta-acquires-limitless)).

## 11. OpenClaw (ex-Clawdbot/MoltBot) and 2026 personal agents

OpenClaw is the dominant open-source personal agent and its memory is **plain Markdown + SQLite hybrid search** ([memory docs](https://docs.openclaw.ai/concepts/memory), [dreaming docs](https://docs.openclaw.ai/concepts/dreaming)): `USER.md` (directives, small budget) and `MEMORY.md` (curated durable facts) load at session start — truncated to a "bootstrap budget" if too long; `memory/YYYY-MM-DD.md` daily notes are *searchable, not injected* (today+yesterday load on `/new`); `memory_search` is vector+keyword over SQLite (OpenAI embeddings default; Postgres/pgvector experimental); a **silent "memory flush" turn** runs before compaction so the agent writes to the daily note (new text only; replays rejected). **Dreaming** (default on, cron `0 3 * * *`): light (stage) → REM (themes) → deep (the only phase that writes `MEMORY.md`) with a weighted score (relevance .30, frequency .24, query diversity .15, recency .15, consolidation .10, richness .06), `untrusted`/`system` provenance excluded, recalled context stripped so it can't be re-learned (the exact Mem0 feedback-loop bug), max 25% prior-entry loss, `DREAMS.md` diary. Honcho, Mem0 and Cognee all ship OpenClaw plugins. Community complaint: bloated MEMORY.md slows startup; loading rules differ across versions.

Other 2026 "life memory" products: **Engramme** (Harvard spinout; "Large Memory Models", "memorome", proactive surfacing, iOS beta, reported $100M raise talks — no technical disclosure, [Slashdot](https://hardware.slashdot.org/story/26/04/12/0640253/neuroscientist-ai-powered-startup-aims-to-transform-human-cognition-with-perfect-infinite-memory)); Show HN entries like a 24/7 home-server Claude agent with "small always-loaded core + SQLite recall searched on demand" ([HN](https://news.ycombinator.com/item?id=47132125)), Mwe-MCP (per-user wikis with inline ACLs), MemoryGate, Mengram, a LoCoMo-52% "biological decay" store; "Second Brain for AI" on Product Hunt (self-hosted on Cloudflare). A **MemGhost** attack (Jul 2026) showed one email can plant a persistent false memory in an agent ([The Hacker News](https://thehackernews.com/2026/07/new-memghost-attack-plants-persistent.html)). Aggregator claims of an "Anthropic Dreaming feature" and Meta "Muse Active Memory" were **[unverified]**.

## What this means for a "whole-life" single-chat assistant

1. **Nobody has solved contradictions in-band.** Mem0 gave up on inline UPDATE/DELETE for cost reasons; Zep invalidates edges; OpenAI/OpenClaw/Letta/Mem0 all moved conflict resolution to a nightly "dream". Plan for an append-only event log plus a derived "current view" rebuilt offline.
2. **The feedback loop is the #1 silent killer**: whatever you inject must be tagged so the extractor never re-ingests it (OpenClaw strips "recalled" context; Mem0 didn't and produced 808 Vim entries).
3. **Always-injected profiles create the complaints users hate** (bleed-through, dossier feel). Both OpenAI and Anthropic now expose source attribution and a visible editable view; Claude and OpenClaw additionally keep retrieval as visible tool calls. Budget the always-on block (Claude Code: 25KB; OpenClaw: "bootstrap budget"; Letta: char limits) and make the rest searchable.
4. **Time matters**: ChatGPT ages facts, Zep stores validity windows, Mem0 added temporal reasoning, Hindsight anchors everything in time. Verbatim dates beat LLM paraphrase ([arXiv 2601.00821](https://arxiv.org/pdf/2601.00821)).
5. **Security**: memory is now an attack surface (bio-tool injection, MemGhost); gate writes by provenance like OpenClaw does.
